## Verification notes

**2026-11-20, first version, environment without network access.** Packages could not be installed, so Vite, Vitest, jsdom, Testing Library, the React type packages, and `typebox` were not available. What was run instead:

- `esbuild` bundled `web/src/main.tsx` (including the shared contracts and fixtures through aliases) without errors. `typebox` was replaced by an inert stand-in for this check, because the web app imports only types and the ranking helpers from `shared/`.
- The 12 tests in `web/src/test/lib.test.ts` ran under a small ad-hoc runner that mimics `describe`/`it`/`expect`. All 12 passed. This is not a Vitest run.
- The landing page, not-found page, skeleton, status line, toolbar, gauge, specs card, and all five path cards were server-rendered with `react-dom/server` from the laptop fixtures without errors. Effects do not run in server rendering, so interaction is not covered.
- `app.test.tsx` (component tests) has not been executed. `npm run typecheck`, `npm test`, `npm run build -w web`, and the browser review have not been run.

No criterion is marked `Pass` on this basis.

**2026-11-20, amendment (FR-014 to FR-016), same limits as above.** The defect behind FR-016 was reported by the team with two screenshots of the gauge (Pass it on at 64 %, Upgrade at 95 %). Cause: the SVG large-arc flag was set for ranges above 50 %, although the scale never exceeds 180°. Re-checked after the fix with the ad-hoc setup: esbuild bundle builds; 14 of 14 logic tests pass (two new); all five paths render as step blocks from the laptop fixtures (3, 2, 2, 2, 1 steps); placeholders render while the report is pending; the toolbar marks the active path tag and the active priority. Existing criteria AC-001 to AC-013 were not re-run in Vitest or a browser; earlier evidence for them stays as recorded above.

**2026-11-20, second amendment (FR-017, FR-018), same limits as above.** Re-checked with the ad-hoc setup: esbuild bundle builds; 18 of 18 logic tests pass (four new for option views); the path tabs, the option cards, the placeholders, the fallback, and the toolbar markup render from the fixtures without errors. The option data is fictional sample data written for this review (`web/src/api/mockOptions.ts`); it is not a calculator result. AC-001 to AC-017 were not re-run in Vitest or a browser.

**2026-11-20, third amendment (FR-019), same limits as above.** Re-checked with the ad-hoc setup: the esbuild bundle builds and the landing page and not-found page render the footer link. The component test for the link was not executed.

**2026-11-20, after merge into `main`, revision a846d99, Node v24.15.0.** Dependencies installed. `npm run typecheck` passes for shared, server, and web. `npm test` passes: shared 61, server 50, web 20 tests (`lib.test.ts` 12, `app.test.tsx` 8). `npm run build -w web` builds the bundle (270 kB, 84 kB gzip). Rows stay `Not run` where the stated method also needs a manual or browser check, or where a part of the scenario has no test yet (AC-004 error state, AC-008 dropdown re-request, AC-010 partial-scan note).

**2026-11-20, scan sessions (T-010).** AC-002 previously expected a 22-character session ID. The session ID format was decided as 26 Crockford base32 characters (`DESIGN.md`), and the scenario text was updated to match; the requirement FR-002 is unchanged. Checks: `web` 20 tests (router accepts only the new session format), `server/test/sessions.test.ts` 6 tests, scanner `internal/run` session tests. End-to-end on the command line: a session was created, the scanner was downloaded with the trailer, the downloaded copy read its ID, posted progress, and uploaded, and the event stream delivered `complete` with the device ID. The session ID did not appear in the server log.
